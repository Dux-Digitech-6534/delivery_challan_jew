# Frappe Generation Rules

## Purpose

This file defines the mandatory method for creating Frappe framework objects for this project.

The user has specifically instructed that DocTypes, Pages, Reports, Workspaces, Print Formats, and similar Frappe objects should not be manually created from scratch.

They must first be generated by Frappe/bench, preferably through bench console scripts or Frappe UI in Developer Mode.

## Reason

System-generated Frappe objects correctly create:

- folder structure
- __init__.py files
- JSON metadata
- Python controller files
- JavaScript files
- module references
- boilerplate structure
- internal Frappe metadata

This reduces errors compared to manually creating folders and JSON files.

## Strict rule

Do not manually create a new DocType folder or JSON file from scratch.

Generate first. Edit later.

## App creation

The app itself should be created on the dev server using:

bench new-app delivery_challan_custom

Then installed using:

bench --site erp.jewonline.in install-app delivery_challan_custom

## Recommended server commands

SSH:

ssh frappe@187.127.132.58

Go to bench:

cd ~/frappe-bench

Create app:

bench new-app delivery_challan_custom

Install app:

bench --site erp.jewonline.in install-app delivery_challan_custom

## DocType creation preference

Use Frappe UI in Developer Mode or bench console.

Since the user prefers bench console, provide a bench console script that creates DocTypes using frappe.get_doc.

Start console:

bench --site erp.jewonline.in console

Then run a Python script that creates:

- Module Def if required
- Delivery Challan DocType
- Delivery Challan Item child DocType

After saving DocTypes, Frappe should generate the files inside the app.

## Cache and process reload rule

For Frappe coding on the development server, clearing cache is mandatory after migrations, DocType metadata changes, Python controller changes, and JS changes:

bench --site erp.jewonline.in clear-cache

After migration or backend Python changes, reload/restart the running bench processes before browser verification. If normal bench restart asks for a password, use a safe HUP-based process reload for the relevant bench processes where suitable.

For JS changes, also run:

bench build --app delivery_challan_custom
bench --site erp.jewonline.in clear-cache

Then reload/restart bench processes and verify the browser again.

## Suggested creation order

1. Create app using bench new-app.
2. Install app on erp.jewonline.in.
3. Ensure developer_mode is enabled for the site if required.
4. Create Module Def if required.
5. Create Delivery Challan Item child DocType.
6. Create Delivery Challan parent DocType.
7. Run bench migrate.
8. Run bench --site erp.jewonline.in clear-cache.
9. Reload/restart the running bench processes.
10. Confirm the site opens without Internal Server Error.
11. Confirm files generated.
12. Only then edit generated Python, JS, and JSON files.

## Developer mode check

Check site config:

bench --site erp.jewonline.in show-config

If developer_mode is not enabled:

bench --site erp.jewonline.in set-config developer_mode 1
bench --site erp.jewonline.in clear-cache

## Important

If Codex is running locally and cannot directly access the server, it should prepare:

1. exact bench console script
2. exact commands to run on server
3. expected generated file paths
4. follow-up editing instructions

The user or an SSH-capable Codex session will run the commands on the dev server.

## Do not do this

Do not manually create:

- doctype folder
- doctype JSON
- Python controller
- JS file
- report JSON
- page JSON

unless Frappe generation fails and the user explicitly approves manual recovery.
